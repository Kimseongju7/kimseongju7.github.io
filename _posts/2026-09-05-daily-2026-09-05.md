## 요약

이미지로 받은 C++ 코드를 직접 돌려 보며 `std::transform`을 파고든 날. 뉴턴 냉각 법칙을 제자리 변환으로 적용하는 예제였는데, 그 김에 **`transform`과 `for_each`의 차이가 "결과를 어디에 쓰느냐"** 하나로 갈린다는 것까지 정리했다.

오후에는 미리보기 앱이 죽은 크래시 리포트를 읽었다. 주소를 힙 블록 경계와 비교해 **버퍼 언더플로**임을 짚고, 스택에 내 코드가 없다는 점에서 **Apple 프레임워크 내부 문제**로 결론 냈다.

**[진단] macOS 미리보기 앱 크래시 리포트 분석**

- ✨ 크래시 스레드의 스택을 위에서 아래로 읽으면 경로가 드러났다 — 썸네일 큐에서 PDF 페이지 썸네일을 그리다가 → PDFKit이 주석(annotation)을 그리고 → AnnotationKit이 속성 문자열에 속성을 추가하다가 → 내부 `NSMutableRLEArray`가 `memmove` 중 터졌다.

## 배운 것

<!-- claude-recall-learn:rlatjdwn:start -->

**`std::transform` — 다른 언어의 `map`에 해당한다**

- ✨ `<algorithm>` 헤더의 표준 알고리즘으로, **범위의 각 원소에 함수를 적용해 그 결과를 다른 범위에 써 넣는다.** 형태는 `std::transform(first, last, d_first, op)`이고 반환값은 마지막으로 쓴 위치의 다음 반복자다.
- ✨ 손으로 풀면 `for (auto it = first; it != last; ++it, ++d_first) *d_first = op(*it);` 이다. `op`는 함수 포인터·람다·함수 객체 모두 가능하다.
- ✨ **입력 범위와 출력 위치를 같게 주면 제자리(in-place) 변환**이 된다(`temp.begin(), temp.end(), temp.begin()`). 출력이 다른 벡터여도 되지만 **그 벡터는 미리 크기가 충분해야 하고**, 새 벡터에 밀어 넣으려면 `std::back_inserter`를 쓴다.

**`transform`과 `for_each`의 차이는 "결과를 어디에 쓰느냐"다**

- ✨ `transform`은 **함수의 반환값을 출력 범위에 저장**하고, `for_each`는 **반환값을 버리고 원소마다 함수를 호출만** 한다. 그래서 `transform`은 출력 반복자가 필요하고 `for_each`는 필요 없다.
- ✨ 원소를 고치는 방식도 갈린다 — `transform`은 **반환값으로 덮어쓰고**, `for_each`는 **참조로 받아 직접 수정**한다. 호출 순서는 `for_each`만 앞에서부터 보장된다.
- ✨ 결과가 같은 경우가 많아서, 실제 선택 기준은 성능이 아니라 **의도를 어떻게 읽히게 할 것인가**다. "값 → 새 값 매핑"이면 `transform`, "원소마다 무언가 실행"이면 `for_each`.

**크래시 리포트는 위에서 아래로, 주소는 경계와 비교해서 읽는다**

- ✨ **`EXC_BAD_ACCESS` + `KERN_INVALID_ADDRESS`** 는 잘못된 주소를 건드렸다는 뜻이고, 그 주소를 **VM Region 정보의 힙 블록 경계와 비교**하면 오버플로인지 언더플로인지가 갈린다. 이번엔 블록 시작보다 앞이라 언더플로였다.
- ✨ **레지스터 값도 단서다.** `memmove`의 길이 인자가 음수로 해석되는 값이면, 터진 지점이 아니라 **그 전에 이미 내부 카운트가 깨져 있었다**는 뜻이다.
- ✨ 스택은 **위에서 아래로 읽으면 "무엇을 하다가"** 가 나온다. 프레임워크 이름이 이어지는 구간(PDFKit → AnnotationKit → Foundation 내부)만 나오고 내 코드가 없으면 **앱·시스템 쪽 문제**로 판단할 수 있다.

## 메모

- 이미지 코드의 **람다 매개변수 이름 `temp`가 바깥 벡터 `temp`를 가린다.** 컴파일은 되지만 읽기에 헷갈리니, 직접 쓸 때는 이름을 바꾸는 게 낫다.
- `transform`으로 새 벡터에 결과를 담으려면 **출력 벡터의 크기를 미리 확보**하거나 `std::back_inserter`를 써야 한다.
- 미리보기 크래시는 사용자 쪽 잘못이 아니라 대응할 게 없다. 같은 증상이 반복되면 그때 PDF 주석이 많은 파일을 피하는 정도만 참고.
