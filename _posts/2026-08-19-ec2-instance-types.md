## 한 줄 정의
EC2 인스턴스 유형(instance type)은 vCPU·메모리·스토리지·네트워크의 **비율과 크기를 용도별로 미리 조합해 둔 서버 사양 카탈로그**이며, `c7gn.xlarge` 같은 이름만 읽어도 "어떤 계열·몇 세대·무슨 옵션·얼마나 큰 서버"인지 알 수 있다.

---

## 자세히
EC2는 물리 서버를 [하이퍼바이저](/posts/hypervisor/) 위에서 잘라 빌려주는 서비스라, "얼마나 잘라 줄까"를 정하는 규격표가 필요하다. 그게 인스턴스 유형이다. 종류가 수백 개라 외울 수 없고 외울 필요도 없다 — 이름 규칙만 알면 처음 보는 유형도 해석된다.

### 이름 읽는 법
`c7gn.xlarge`를 예로 들면 마침표 앞이 *인스턴스 패밀리*, 뒤가 *크기*다.

- `c` — **계열(series)**: 이 서버가 무엇에 최적화됐는지 (c = 컴퓨팅 최적화)
- `7` — **세대(generation)**: 숫자가 클수록 최신 하드웨어·더 좋은 가성비
- `gn` — **옵션**: 프로세서 종류와 추가 기능 (g = AWS Graviton, n = 네트워크·EBS 강화)
- `xlarge` — **크기(size)**: 같은 계열 안에서 몇 배짜리인지

### 세대는 최신이 기본값이다
같은 계열 안에서 하드웨어만 갈아끼운 것이라 성격(vCPU:메모리 비율)은 그대로고, CPU 세대·메모리 규격(DDR4 → DDR5)·네트워크와 EBS 대역폭이 좋아진다. 보통 세대당 가격 대비 성능이 15~30% 개선된다.

핵심은 **신세대가 구세대보다 비싸지 않은 경우가 많다**는 점이다. 성능이 오른 만큼 단가는 비슷하거나 낮게 책정되곤 해서, 특별한 이유가 없으면 **그 리전에서 쓸 수 있는 최신 세대를 고르는 게 기본값**이다.

### 세대 번호에서 헷갈리기 쉬운 것들
- **계열·프로세서끼리 동기화돼 있지 않다.** `t3`와 `t4g`는 숫자 차이 하나지만 t3는 Intel, t4g는 Graviton2로 아키텍처 자체가 다르고, `m6i`(Intel)·`m6a`(AMD)·`m6g`(Graviton2)는 숫자가 같아도 같은 칩이 아니다. 숫자는 "그 프로세서 라인 안에서 몇 번째"로 읽어야 한다. Graviton은 `A1`=Graviton1, `*6g`=Graviton2, `*7g`=Graviton3, `*8g`=Graviton4로 매핑되고, Intel 라인은 대략 `*6i`=Ice Lake, `*7i`=Sapphire Rapids, `*8i`=Granite Rapids(Xeon 6)로 이어진다.
- **크기의 숫자와 헷갈리면 안 된다.** `m7i.2xlarge`에서 `7`은 세대, `2x`는 크기 배수이고 `48xlarge`의 48은 세대와 무관하다.
- **최신 세대가 모든 리전에 있는 건 아니다.** 서울 리전(ap-northeast-2)은 us-east-1보다 신세대 도입이 늦는 편이라, 코드에 박아둔 인스턴스 유형이 리전에 따라 안 뜰 수 있다.
- **숫자가 세대가 아닌 예외도 있다.** `u-6tb1.metal`의 `6tb`는 세대가 아니라 **메모리 용량 6 TiB**를 뜻하고, `gb200`·`b200` 같은 이름의 숫자는 NVIDIA **Blackwell** GPU 모델명이 그대로 들어간 것이다. `p5`·`g6`처럼 GPU 계열은 숫자가 곧 GPU 세대를 따라가는 편이다.

### 계열을 가르는 진짜 기준은 vCPU 대 메모리 비율이다
같은 4 vCPU라도 계열마다 붙는 메모리가 다르다. 대략 C 계열은 vCPU당 2 GiB, M 계열은 4 GiB, R 계열은 8 GiB, X 계열은 16 GiB 이상이다.

그래서 "CPU를 갈아 쓰는데 메모리는 별로 안 쓰는" 워크로드에 R 계열을 쓰면 안 쓰는 메모리 값을 내는 셈이고, 반대로 인메모리 캐시에 C 계열을 쓰면 메모리가 먼저 터진다. 인스턴스 유형 선택이 곧 비용 최적화인 이유다.

### 계열은 크게 다섯 카테고리로 묶인다
- **범용** — `M`(균형), `T`(버스터블), `Mac`(macOS 빌드용). 웹 서버, 애플리케이션 서버, 중소형 DB처럼 특별히 한쪽에 치우치지 않은 일반 워크로드의 기본값.
- **컴퓨팅 최적화** — `C`. vCPU당 메모리가 가장 적고 CPU 성능이 높다. 영상 인코딩, 배치 연산, 고성능 웹 서버, CI 러너, CPU 추론.
- **메모리 최적화** — `R`(기본), `X`·`U`·`Z`(초고용량 메모리 / 고클럭). 인메모리 DB(Redis, SAP HANA), 대용량 캐시, 실시간 분석.
- **스토리지 최적화** — `I`·`Im`·`Is`(NVMe 로컬 SSD, 높은 IOPS), `D`(대용량 HDD). NoSQL, 데이터 웨어하우스, 분산 파일시스템.
- **가속 컴퓨팅** — `P`·`G`(NVIDIA GPU), `Trn`(AWS Trainium, 학습), `Inf`(AWS Inferentia, 추론), `F`(FPGA), `VT`(영상 트랜스코딩). 딥러닝 학습·추론, 그래픽 워크로드. 여기에 HPC 전용 `Hpc` 계열이 따로 있다.

### T 계열(버스터블)은 성격이 다르다
T 계열은 상시 최대 성능을 주는 대신 **기준 성능(baseline)** 만 보장하고, 그보다 덜 쓴 만큼 **CPU 크레딧**을 쌓아 뒀다가 순간적으로 부하가 튈 때 그 크레딧을 태워 최대 성능을 낸다.

평소 한가하다가 가끔 튀는 소규모 웹사이트·개발 서버·마이크로서비스에 싸고 잘 맞지만, 계속 CPU를 100%로 쓰는 워크로드에서는 크레딧이 바닥나 성능이 뚝 떨어지거나(standard 모드) 추가 요금이 붙는다(unlimited 모드). "왜 갑자기 느려졌지?"의 단골 원인이다.

### 옵션 문자와 크기
**옵션 문자(접미사)** 는 같은 계열의 변종을 나타낸다. 프로세서는 `i`(Intel), `a`(AMD), `g`(AWS Graviton, Arm 기반)로 갈리고, 그 위에 기능 문자가 붙는다 — `d`는 인스턴스 스토어(로컬 NVMe) 추가, `n`은 네트워크·EBS 대역폭 강화, `e`는 메모리/스토리지/GPU 메모리 확장, `z`는 고클럭 CPU, `b`는 블록 스토리지 최적화, `flex`는 상시 최대 성능 대신 값을 깎은 유연 옵션이다.

최신 세대(M8g·C8g·R8g 등)의 `g`는 Graviton4로, 같은 성능을 x86보다 싸게 내는 경우가 많아 요즘 기본 후보로 자주 오른다. 다만 Arm이라 컨테이너 이미지·바이너리가 arm64를 지원해야 한다.

**크기(size)** 는 `nano < micro < small < medium < large < xlarge < 2xlarge < … < 48xlarge` 순으로 커지고, 대체로 한 단계 올라갈 때마다 vCPU·메모리·가격이 **2배**가 된다. `metal`은 하이퍼바이저 없이 물리 서버를 통째로 쓰는 베어메탈이다.

### 유형과 구매 옵션은 다른 축이다
유형(m7g.large 같은 사양)을 고르는 것과, 그걸 [온디맨드](/posts/on-demand/)로 살지 예약 인스턴스/Savings Plans로 약정할지 스팟으로 싸게 쓸지를 고르는 것은 별개의 선택이다. 두 축을 조합해서 비용을 맞춘다.

## 예시
계열별 성격 요약:

| 계열 | 카테고리 | vCPU당 메모리(대략) | 대표 용도 |
|---|---|---|---|
| `T` | 범용(버스터블) | 1~4 GiB | 개발 서버, 저트래픽 웹, 가끔 튀는 워크로드 |
| `M` | 범용 | 4 GiB | 웹/앱 서버, 중소형 DB, 마이크로서비스 |
| `C` | 컴퓨팅 최적화 | 2 GiB | 인코딩, 배치 연산, CI, CPU 추론 |
| `R` | 메모리 최적화 | 8 GiB | Redis, 인메모리 분석, 대형 DB |
| `X`/`U` | 초대용량 메모리 | 16 GiB~ | SAP HANA, 초대형 인메모리 DB |
| `I`/`D` | 스토리지 최적화 | — (로컬 디스크가 핵심) | NoSQL, 데이터 웨어하우스, 로그 저장 |
| `P`/`G` | 가속 컴퓨팅 | — (GPU가 핵심) | 딥러닝 학습(P), 추론·그래픽(G) |
| `Trn`/`Inf` | 가속 컴퓨팅 | — (AWS 전용 칩) | 학습(Trainium), 추론(Inferentia) |

이름 해석 연습:
- `t3.micro` — 범용 버스터블, 3세대, 옵션 없음(Intel), 아주 작은 크기. 프리 티어 단골.
- `m7g.large` — 범용, 7세대, Graviton3(Arm), large.
- `c7gn.xlarge` — 컴퓨팅 최적화, 7세대, Graviton + 네트워크 강화, xlarge.
- `r6id.2xlarge` — 메모리 최적화, 6세대, Intel + 로컬 NVMe 디스크, 2xlarge.
- `p5.48xlarge` — GPU 가속, 5세대, 최대 크기. LLM 학습용.
- `m5.metal` — 범용 5세대 베어메탈(물리 서버 통째).

선택 순서(실무 감각):
1. GPU/전용 칩이 필요한가? → `P`/`G`/`Trn`/`Inf`
2. 로컬 고속 디스크가 병목인가? → `I`/`D`
3. 메모리가 먼저 부족한가? → `R`(더 부족하면 `X`/`U`)
4. CPU가 먼저 부족한가? → `C`
5. 다 애매하면 → `M`, 트래픽이 작고 들쭉날쭉하면 → `T`
6. 계열을 정했으면 세대는 최신으로, 프로세서는 arm64가 되면 `g`(Graviton) 우선 검토
7. 크기는 작게 시작해서 [Amazon CloudWatch](/posts/amazon-cloudwatch/) 지표 보고 조정하고, 대수 자체는 [Auto Scaling](/posts/amazon-ec2-auto-scaling/)에 맡긴다
