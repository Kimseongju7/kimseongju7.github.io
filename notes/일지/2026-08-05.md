**CI·자동화 런이 조용히 어긋나는 두 가지 방식**

- ✨ **같은 코드인데 push 런만 실패하고 PR 런은 통과한다면 코드가 아니라 플레이크를 의심**해야 한다. 이번엔 CI 의 dev 서버 온디맨드 컴파일이 느려 기본 5초 expect 타임아웃을 넘긴 것이었고, retry 로도 같은 지점에서 실패했다. **retry 가 못 잡는 플레이크는 타임아웃 자체가 원인**인 경우가 많아 CI 전용 타임아웃 상향이 정답이었다.
- ✨ 리뷰 봇은 **멘션 오타 하나로 죽는다.** `@cladue` 라 워크플로의 `@claude` 조건에 안 걸렸는데, 이때 워크플로는 "조건 미충족으로 스킵"된 런을 남긴다 — **런 기록이 있다고 해서 리뷰가 돈 게 아니다.**

**"영원히 나오지 않는 값"을 계약에 미리 넣지 않는다**

- ✨ `matching.status` 의 `failed` 는 AI 매칭 본체가 구현돼야만 발생할 수 있는 값이다. 지금 계약을 확정하면 프론트에 **죽은 값**을 주게 되고, 본체가 들어올 때 계약을 또 손대야 한다.
- ✨ 그래서 **계약 필드는 그 값을 실제로 만들어낼 수 있는 구현과 함께 나가는 게 맞다.** 프론트가 추론 로직을 걷어내는 이득도 어차피 본체와 같이 나갈 때 동일하게 얻는다.

**mock 데이터에 실파일을 쓰면 그대로 public 에 노출된다**

- ✨ 테스트용으로 넣은 docx 가 실데이터였다. 위험한 건 본문이 아니라 **작성자 메타데이터의 실명**과 **삽입 이미지 안의 정보**(이메일·집주소·카드 뒤 4자리·승인번호)였다.
- ✨ 프론트 `public/` 아래 mock 자산은 **무인증 정적 경로**다. 앱에 로그인하지 않아도 URL 만 알면 받아진다. 문서 파일을 샘플로 쓸 때는 본문뿐 아니라 **메타데이터와 삽입 이미지까지** 확인해야 하고, 가능하면 처음부터 합성 문서를 쓰는 게 맞다.
- ✨ 이번엔 **푸시 전이라 로컬 제거로 끝났다.** 푸시 이후였다면 git 히스토리에 남아 훨씬 복잡해졌을 것이다.

**dev 서버 가동 중에 프로덕션 빌드를 같은 `.next` 에 돌리면 안 된다**

- ✨ 검증 게이트로 돌린 `pnpm build` 가 **dev 서버가 서빙 중이던 `.next` 캐시를 덮어써서** `Cannot find module './975.js'` 500 이 났다. 같은 뿌리에서 pdfjs 텍스트 레이어 CSS 가 빠져 **하이라이트가 캔버스 위 오버레이가 아니라 페이지 아래에 별도 텍스트로 흘러내리는** 증상까지 나왔다.
- ✨ 여기서 중요한 건 **증상이 "코드가 깨진 것처럼" 보였다는 점**이다. 최신 빌드를 Chromium·WebKit 양쪽, 좁은 폭(1100px)·넓은 폭(1728px)에서 좌표 계측으로 재현해 보니 전부 정상이었고, 범인은 사용자 탭의 스테일 세션이었다.
- ✨ 조치는 프로세스 종료 → `.next` 삭제 → 재기동. 재발 방지로 텍스트 레이어 CSS 를 lazy 청크가 아니라 **루트 레이아웃에서 항상 로드**하도록 승격했다(`f3e39e9`).

**브라우저에서 도는 것은 브라우저에서 본다**

- ✨ 뷰어 코드는 브라우저에서 실행되므로 **`console.log` 는 dev 서버 터미널에 절대 안 찍힌다.** 브라우저 콘솔(Cmd+Option+J → Console)에서 `anchor-debug` 로 필터해야 보인다. 굳이 터미널로 받으려면 dev 전용 로그 API 라우트(`POST /api/dev-log`)로 릴레이하는 수밖에 없다.

- 킬링 피쳐가 어느 정도 완성되었으면 서브 피쳐를 고민하면서 완성도를 키워야 한다.
- 개발에서 정의한 타겟 유저가 기능 설계의 판단 기준이 되었다면, 마케팅에서의 타겟 유저는 우리 서비스의 키워드를 정의하는 기준이 된다.
- 대부분의 광고 알고리즘은 검색 기록으로 이루어지기에, 타겟 유저가 어떤 걸 검색할지 추측해 우리 서비스의 키워드를 정의한 뒤 키워드 광고 같은 것을 설정해야 한다.
