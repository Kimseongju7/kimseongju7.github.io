## 배운 것

<!-- claude-recall-learn:rlatjdwn:start -->

**sklearn의 이름과 구조**

- ✨ **설치할 때는 `scikit-learn`, 코드에서 부를 때는 `sklearn`** 이다. `pip install scikit-learn` → `import sklearn`으로 둘이 다르다. 별칭은 문제가 주는 대로 쓴다.
- ✨ 기능별로 모듈이 갈린다 — 나누기·`GridSearchCV`는 `sklearn.model_selection`, 스케일러·`LabelEncoder`는 `sklearn.preprocessing`, MAE·accuracy는 `sklearn.metrics`.
- ✨ 모델은 소속이 헷갈린다. `DecisionTree...`는 **`sklearn.tree`** 지만 `RandomForest...`는 **`sklearn.ensemble`** 이다. 랜덤포레스트는 트리를 여러 개 모아 쓰는(ensemble) 방식이라 소속이 다르다. `LinearRegression`·`LogisticRegression`은 `sklearn.linear_model`.

**스케일러는 큰 숫자가 계산을 독점하는 걸 막는다**

- ✨ 스케일러는 **컬럼 간 값의 범위 차이를 줄이는 것**이 전부다. `Distance`는 수백~수만인데 `Weekday`는 0~6, 원-핫 컬럼은 0 또는 1이라, 숫자만 보면 `Distance`가 수천 배 중요해 보인다. 실제로는 단위가 다를 뿐이다.
- ✨ 문제가 되는 건 **거리로 계산하는 모델들**이다. 두 행의 차이를 컬럼별 차이의 제곱합으로 재면 `(5000)² + (3)²`처럼 되어 **`Weekday`가 있으나 없으나 결과가 같아진다.** 경사하강법(딥러닝, 로지스틱회귀)도 축마다 스케일이 다르면 최솟값을 찾는 경로가 지그재그로 튀어 학습이 느려지거나 발산한다.

**sklearn·pandas는 복수형을 잘 쓴다**

- ✨ 하루에 같은 계열로 세 번 걸렸다 — `value_count` → **`value_counts`**, `feature_importance_` → **`feature_importances_`**, `min_sample_split` → **`min_samples_split`**. 샘플이 여러 개라 복수형이다.
- ✨ 오픈북에서 30초면 확인되는 것들이라, 헷갈리면 감으로 쓰지 말고 공식 문서를 여는 게 맞다.

**에러가 난 자리와 원인이 있는 자리는 다르다**

- ✨ 노트북에서 가장 흔한 원인은 **변수 덮어쓰기**다. 연습 셀에서 본문의 `X`·`y`·`dt`를 재사용하면 이후 셀이 통째로 오염된다. `All arrays must be of the same length`는 컬럼 이름 개수와 중요도 점수 개수가 안 맞는다는 뜻인데, 진짜 원인은 몇 셀 위에서 `X`를 바꾼 것이었다.
- ✨ `Found input variables with inconsistent numbers of samples: [2000, 7997]`도 마찬가지였다. 12-1이 아니라 **9-1에서 `X_valid = rs.transform(X_train)`으로 검증 자리에 훈련셋을 넣은 것**이 원인이었다. 트레이스백은 **맨 아래 한 줄부터** 읽고, 길이가 안 맞으면 그 변수를 마지막으로 건드린 셀을 거슬러 올라가야 한다.

**Jupyter의 셀 출력은 "잔상"이다**

- ✨ 셀 아래 출력은 **마지막으로 실행했을 때의 결과**다. 코드를 고쳐도 다시 실행하기 전까지 옛 에러가 그대로 붙어 있어서, 이미 고친 문제가 계속 나는 것처럼 보인다.
- ✨ 판별법은 **왼쪽 대괄호 숫자**다. `[ ]`이거나 다른 셀보다 번호가 작으면 지금 화면의 코드가 아니다. 이걸로 하루에 두 번 헤맸다.

**짝을 이루는 줄은 한쪽만 고치게 된다**

- ✨ 오늘 최대 약점으로 기록된 패턴이다. `dt`와 `rf`처럼 나란히 가는 두 줄에서 **한쪽만 고치고 다른 쪽을 놓친다.** `rf.predict(X_valid)`는 고쳤는데 `dt.predict(X_train)`은 그대로였고, `rf_mae`가 `y_pred_dt`를 쓰는 것도 같은 계열이다.
- ✨ 특히 위험한 건 **에러가 안 나는 경우**다. 길이만 맞으면 두 값이 똑같이 나오고 단답이 통째로 틀린다. 답안 셀 단답도 **클래스 이름이 아니라 모델 이름**을 묻는다 — `RandomForestRegressor`가 아니라 `RandomForest`.

**GridSearchCV는 4단계 골격으로 외운다**

- ✨ 모델 만들고 → 후보 딕셔너리(`param_grid`) 만들고 → 감싸고 → `fit`. **하이퍼파라미터는 모델이 아니라 `param_grid`에 리스트로** 넣고, 모델에는 `random_state`만 준다.
- ✨ 뒤 문항과 연결된다 — GridSearch를 쓴 쪽은 `gs_rf.best_estimator_.`로 접근하고, 안 쓴 쪽은 `rf.`로 바로 쓴다. **여기가 막히면 10·11·12 세 문항이 연쇄로 죽는다.**
