## 배운 것

<!-- claude-recall-learn:codex:start -->

**스레드를 데이터에 대응시키는 법 — 인덱스 계산 · 범위 검사 · 블록 수**

- ✨ `int i = blockIdx.x * blockDim.x + threadIdx.x` — 스레드는 **블록**이라는 묶음에 속하고, `블록 번호 × 블록당 스레드 수 + 블록 안 번호`가 그 스레드가 맡을 배열 인덱스가 된다. 전부 0부터 센다(블록당 4개일 때 1번 블록의 2번 스레드 → `i = 6`).
- ✨ `if (i < n)`이 필요한 이유는 **데이터 개수보다 스레드를 많이 띄울 수 있기 때문**이다. 32스레드로 `n = 5`를 처리하면 0~4번만 결과를 쓰고 나머지 27개는 아무것도 하지 않는다. 그래서 출력 배열 뒤쪽 27칸은 **0이 보장되지 않는다** — `cp.empty()`는 공간만 잡고 초기화하지 않아서, 0으로 보여도 우연이다.
- ✨ 필요한 블록 수는 **올림 나눗셈** `(n + block - 1) // block`으로 구한다. 그냥 `257 // 256`은 1이라 마지막 하나를 놓친다. `block - 1`을 먼저 더해 **남는 데이터가 있으면 블록을 하나 더** 배정하는 것.
- ✨ 실행 인자의 `(1,)`, `(32,)`는 **차원별 배치를 지정하는 튜플**이다. CUDA는 1~3차원을 지원해 `(8, 4)`는 x 8 × y 4가 된다. 파이썬에서 `(32)`는 그냥 숫자라 **쉼표를 붙여야 튜플**이 된다.

**`extern "C"`는 네임 맹글링을 막는 장치다**

- ✨ C++ 컴파일러는 함수 이름에 매개변수 타입 같은 정보를 섞어 저장한다 — 이게 **네임 맹글링(name mangling)** 이다. 그래서 `affine`이 내부적으로 다른 이름이 되어 버린다. `extern "C"`를 붙이면 변형을 막아 `make_kernel(src, "affine")`처럼 **문자열 이름으로 커널을 찾을 수 있다.**
- ✨ 코드 전체를 C로 바꾼다는 뜻이 아니다. `extern` 단독 용법("이 변수·함수의 정의는 다른 곳에 있다")과도 달라서, 여기서는 **연결 방식 지정**이라 바로 뒤에 함수 본문을 정의해도 된다.
- ✨ `affine`은 CUDA 예약어가 아니라 **그냥 붙인 함수 이름**이다. 수학의 아핀 변환(`ax + b`)에서 따온 것으로, 이 커널이 `y = 2x + 1`을 계산해서 그렇게 부른 것. 바꾸려면 찾는 쪽 문자열도 같이 바꾸면 된다.

**`cp`(CuPy)와 `np`(NumPy)는 배열이 놓이는 메모리가 다르다**

- ✨ `np.ones(5)`는 **CPU 메모리**에, `cp.ones(5)`는 **GPU 메모리**에 배열을 만든다. `cp.asarray(x)`가 CPU → GPU 복사, `cp.asnumpy(dy)`가 GPU → CPU 복사다. 변수 이름 앞의 `d`는 device(GPU)를 나타내는 관례다.
- ✨ `ones` · `zeros` · `empty`의 차이는 **초기화 여부**다 — `ones`는 전부 1, `zeros`는 전부 0, `empty`는 공간만 확보하고 값을 건드리지 않는다. `empty_like(dx)`는 모양과 자료형이 같은 배열을 만든다.

**Baseline은 숫자 하나가 아니라 비교 설계다**

- ✨ Baseline은 **비교의 기준이 되는 기본 구현이나 측정 결과**다(CPU 100ms를 기준으로 GPU가 20ms면 5배). 최적화를 한다면 **최적화 전 GPU 구현**이 새로운 기준이 될 수도 있다.
- ✨ 핵심은 **공정성**이다 — 입력 데이터 · 정확성 기준 · 측정 범위 · 반복 횟수를 맞춰야 한다. 즉 변인 통제까지 포함하는 개념이라, 시간 숫자만 적어 놓는 것으로는 baseline이 되지 않는다.

**병렬 프로젝트의 차별점은 주제가 아니라 분석 요소다**

- ✨ CPU·GPU 구현 → 정확성 확인 → 시간 비교라는 **틀은 어느 주제로 해도 똑같다.** 달라지는 건 **GPU에 일을 나누는 방법과 성능 차이가 나는 이유**다. 시험지 채점(학생 한 명씩 독립) · 이미지 블러(주변 픽셀 재사용) · 히스토그램(같은 위치에 쓰려는 충돌) · 누적합(앞 결과에 대한 의존성)이 그 예다.
- ✨ 그래서 이름을 바꾸기보다 **분석할 요소 하나를 잡는 것**이 의미 있다 — 전송 비용, 스레드 하나가 처리하는 작업량, 쓰기 충돌 같은 것. "학생 수가 같아도 학생당 문항 수가 늘어나면 GPU가 더 유리해질까?" 처럼 **무엇을 바꿔서 어떤 차이를 확인할 것인가**가 프로젝트의 핵심이다.
