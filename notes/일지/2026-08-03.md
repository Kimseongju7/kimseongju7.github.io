**문서 권위 순서와 하위 문서 동기화**

- ✨ 문서에 권위 순서(target-user → policy → glossary → 기능명세서 → mvp_user_stories)를 세워두면, 정의가 바뀌었을 때 **어느 문서를 정본으로 삼고 어느 쪽을 맞출지 논쟁 없이 정해진다.** 이번 반려 재정의 누락도 "스토리가 최하위"라는 이유로 즉시 상위 문서 기준으로 고칠 수 있었다.
- ✨ 다만 순서가 있다고 동기화가 자동으로 되지는 않는다. 정의를 바꾸는 날 **치환 대상 문서 목록을 먼저 만들어 두지 않으면** 그날 다른 작업을 한 문서가 조용히 누락된다. 이번엔 며칠 뒤 다른 작업(프롬프트 작성) 중에야 발견됐다.

**용어를 바꾸는 판단 기준**

- ✨ "확인 → 해결됨", "반려 → 보완 요청" 개명의 근거가 세 가지였다 — **주체가 모호한가**(누가 확인하는지 안 드러남), **결재 위계를 연상시키는가**(반려는 상급자가 하급자에게 하는 말), **다른 용어와 글자가 겹치는가**("확인"과 "확인 완료"). 감으로 바꾸지 않고 이 세 축으로 걸러내면 논의가 짧아진다.
- ✨ 바꾼 이유를 **결정 기록에 원문 그대로 남기는 것**이 개명 자체보다 중요하다. 나중에 누군가 "왜 굳이 해결됨이지"라고 물을 때 답이 문서에 있어야 같은 논의를 반복하지 않는다.

**레포를 못 읽는 도구에 컨텍스트를 넘기는 법**

- ✨ Claude Design 처럼 저장소 접근이 없는 도구에는 "문서를 읽어라"가 통하지 않는다. **기준 문서의 핵심을 프롬프트 안에 자족적으로 임베드**해야 한다 — 코어 루프, 상태·액션 종류, 권한표, 공식 용어를 프롬프트가 스스로 들고 있어야 한다.

**다이제스트 = 대화 원본을 요약하기 쉽게 압축한 중간 산출물**

- ✨ 일지 자동 요약의 파이프라인은 `~/.claude/projects/*/*.jsonl`(원본) → `extract.py` → **다이제스트(압축 마크다운)** → `notes/일지/YYYY-MM-DD.md` 순이다. 원본 대화가 그대로 요약에 들어가는 게 아니라, 중간에 압축본을 한 번 거친다.
- ✨ `extract.py`(151줄)가 하는 일은 넷이다 — **수집**(모든 프로젝트의 jsonl 을 glob), **필터**(타임스탬프를 KST 날짜로 변환해 그날 것만), **압축**(사용자 발화 600자, assistant 발화는 `ASSISTANT_TEXT_CAP`, 세션당 턴 수는 `MAX_TURNS_PER_SESSION` 상한), **식별**(맨 위 `MACHINE_ID` — macOS 사용자명 기반이라 컴퓨터별로 일지 블록을 나누는 키가 된다).
- ✨ 이 구조를 알아두면 **요약이 부실할 때 어디를 손볼지**가 분명해진다. 긴 세션이 뭉텅 빠졌으면 턴 수 상한, 설명이 토막나 있으면 텍스트 길이 상한이 범인이다.

**`-not -path "*/Library/*"` 는 iCloud 볼트를 통째로 지운다**

- ✨ 홈 디렉터리에서 `find` 를 돌릴 때 `~/Library` 를 빼는 건 보통 옳은 필터다 — 캐시와 앱 지원 파일이 수십만 개라 안 걸러내면 탐색이 몇 분씩 걸린다.
- ✨ 그런데 **iCloud Drive 로 동기화되는 Obsidian 볼트는 `~/Library/Mobile Documents/iCloud~md~obsidian/` 아래에 산다.** 즉 "사용자 문서"인데도 그 필터에 걸려 통째로 사라진다. macOS 에서 문서를 찾을 때는 이 예외를 기억해야 하고, 이번엔 `find` 대신 Claude 프로젝트 디렉터리명에서 경로를 역산한 쪽이 정답이었다.
