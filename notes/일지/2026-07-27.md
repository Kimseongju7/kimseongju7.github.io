## 배운 것

<!-- claude-recall-learn:rlatjdwn:start -->
**PWA · 하이브리드 · 크로스플랫폼 네이티브는 다 다르다**

- ✨ 코드는 셋 다 HTML/CSS/JS일 수 있지만, 구분 축은 **누가 화면을 그리나 + 어떻게 배포하나** 두 개뿐이다. 네이티브는 OS 위젯 + 스토어, 크로스플랫폼 네이티브(Flutter·RN)는 자체 렌더러 + 스토어, 하이브리드는 웹뷰 + 스토어, PWA는 브라우저 본체 + URL(스토어 없음).
- ✨ 최대 오해 지점: **Flutter·React Native는 하이브리드가 아니다.** 웹뷰를 안 쓰고 Skia 같은 자체 렌더러로 직접 그린다. "웹 기술 안 쓰는 크로스플랫폼"이다. 하이브리드는 웹뷰 래핑만 지칭하며 Cordova → Ionic → Capacitor 계보다.
- ✨ "웹앱은 버벅인다"는 인상의 진짜 원인은 셋 중 하나다 — (1) PWA가 아니라 네이티브 앱이 웹뷰를 띄운 하이브리드였거나(브릿지 통신 비용), (2) 웹은 JS가 단일 메인 스레드에서 돌고 그 스레드가 레이아웃과 이벤트를 같이 처리해서 긴 리스트 스크롤 중 프레임이 밀리거나, (3) 그냥 구현이 나빴거나. Excalidraw·Figma는 웹인데도 안 버벅인다.
- ✨ PWA의 경계는 브라우저 샌드박스다. Orca 같은 툴이 PWA가 될 수 없는 건 git worktree 생성이나 CLI 프로세스 spawn 같은 임의의 로컬 프로세스 실행이 원천적으로 불가능해서다.

---

**웹뷰와 PWA의 차이는 "JS 브릿지"다**

- ✨ 둘 다 웹 화면을 그리지만, 웹뷰는 **네이티브 앱의 부품**이고 PWA는 **브라우저 본체**다. 웹뷰 안의 JS는 브릿지로 껍데기 앱의 네이티브 API(카메라·블루투스·생체인증)를 무제한 호출할 수 있고, PWA는 브라우저가 허용한 것만 쓴다. 배포도 스토어 심사 vs URL 즉시로 갈린다.
- ✨ 웹뷰를 왜 쓰냐면 — **가장 큰 이유는 스토어 심사 우회**다. 네이티브 화면은 오타 하나 고치는 데 빌드 → 심사 1~3일 → 사용자 업데이트 대기가 걸리지만, 웹뷰 화면은 서버 배포로 즉시 반영된다. 그래서 이벤트·프로모션처럼 자주 바뀌는 화면은 네이티브로 만들면 운영이 안 된다. 그 외에 약관·FAQ 3벌 → 1벌, PG 결제창·본인인증 같은 남의 사이트 흐름, 인앱 브라우저, 기존 웹 자산 재활용.
- ✨ 현대적 용법은 "웹뷰로 앱 만들기"가 아니라 **"앱 일부를 웹뷰로 채우기"**다. 판단 기준은 변경 빈도 — 자주 바뀌면 웹뷰, 안 바뀌고 손가락이 많이 닿으면 네이티브. 초기 Facebook 앱이 실패한 건 웹뷰 자체가 아니라 **피드 스크롤(=최고 빈도 인터랙션)을 웹뷰에 맡겼기** 때문이다.

**FCM — 푸시는 OS가 유지하는 통로에 얹어 보낸다**

- ✨ FCM(Firebase Cloud Messaging)은 구글의 무료 푸시 전송 인프라다. 핵심 전제는 **서버가 앱에 직접 못 보낸다**는 것 — 앱이 꺼져 있으면 연결이 없으니, OS가 상시 유지하는 통로 하나에 메시지를 얹어야 한다. 그 통로가 FCM이다. 기기별 주소인 registration token을 앱 최초 실행 때 발급받아 서버(Firestore 등)에 저장해두고, 크롤러가 그걸로 발송한다.
- ✨ iOS는 FCM이 직접 꽂지 못하고 **반드시 APNs(Apple Push Notification service)를 경유**한다. FCM이 APNs를 래핑해줘서 앱 코드는 한 벌로 통일되는데, 이게 FCM을 쓰는 최대 이유다.
- ✨ 토큰은 앱 재설치·캐시 삭제 등으로 갱신되므로 **만료 토큰 정리 로직이 필요**하다. 안 하면 죽은 토큰이 DB에 계속 쌓인다.
- ✨ 푸시 제약은 **PWA만의 문제**다. 하이브리드도 껍데기가 진짜 네이티브 앱이라 FCM SDK가 그대로 붙는다. "하이브리드는 반쪽"이라는 말은 렌더링 얘기지 알림 얘기가 아니다. PWA는 Android에서는 웹 푸시가 정상 동작하지만, iOS는 홈 화면에 추가해야만 권한 요청이 가능하다.

**SDD의 핵심 주장 — 유지보수 대상은 코드가 아니라 명세**

- ✨ LLM이 구현을 대신하면서 병목이 구현에서 **입력(무엇을 만들지 정하는 일)**으로 옮겨갔다. 그래서 명세를 1급 산출물로 두고 코드를 파생물로 취급하자는 게 SDD다. 도구별 차이는 결국 "명세를 어디에 두느냐"로 갈린다 — Spec Kit은 레포 안 마크다운, Kiro는 IDE, BMAD는 에이전트 역할 분업, Ouroboros는 Seed YAML.
- ✨ 실패 모드가 뚜렷하다. 스펙 드리프트(코드가 명세에서 멀어짐), 과형식화(문서 만들다 워터폴로 회귀), 컨텍스트 폭발(명세가 커져 모델이 다 못 읽음), 검증 부재(명세대로 됐는지 아무도 확인 안 함). 그래서 규모에 맞게 골라 써야지 전부 다 하면 안 된다.

**온톨로지와 ERD는 묻는 질문이 다르다**

- ✨ ERD가 "이걸 어떻게 저장하나"를 다룬다면 온톨로지는 "이게 대체 무엇인가"를 못 박는다. 그루버의 고전 정의로는 "공유된 개념화에 대한 형식적·명시적 명세"이고, 클래스·속성·관계·공리로 구성된다.
- ✨ 실무에서 왜 필요한지는 "완료한 할 일"이 삭제인지 보관인지 체크 표시인지 사람마다 갈리는 상황을 보면 된다. 코드를 짜기 전에 이 정의를 못 박아야 나중에 스펙이 갈라지지 않는다. 다만 대부분은 RDF/OWL까지 갈 필요 없이 평문 정의로 충분하다.

**브라운필드 / 그린필드**

- ✨ 건축 용어에서 왔다. 그린필드는 백지에서 시작, 브라운필드는 이미 코드가 있는 기존 프로젝트. 에이전트가 이걸 구분하는 이유는 **"인간에게 물어볼 질문"과 "코드가 답할 수 있는 질문"을 갈라내기 위해서**다.
- ✨ "프레임워크가 뭐냐", "DB는 뭐 쓰냐" 같은 사실 확인 질문은 기존 레포라면 이미 코드에 답이 적혀 있다. 그걸 사람한테 되묻는 건 시간 낭비이고, 더 나쁘게는 기억에 의존해 부정확하게 답할 여지를 만든다. 브라운필드 맥락을 걸면 이런 질문은 `[from-code][auto-confirmed]`로 자동 확정되고, 주의력은 "결제 프로바이더 뭐 쓸래" 같은 진짜 결정에만 쓰인다.
- ✨ 맥락 없이 스펙을 뽑으면 기존 코드와 충돌하는 스펙이 나온다 — 이미 있는 유틸을 다시 만들라거나, 실제와 다른 프레임워크를 가정하거나.

---

**caveman은 출력 필터가 아니라 시스템 프롬프트 지시다**

- ✨ "대화창 출력만 줄어드니 파일은 안전하다"가 틀렸다. SessionStart 훅이 규칙을 세션 컨텍스트로 주입하고 UserPromptSubmit 훅이 매 턴 리마인더를 다시 넣는 구조라, Write/Edit로 나가는 문자열과 대화창 문자열을 구분하는 경계 자체가 없다. `caveman-compress`는 아예 대놓고 파일 본문을 압축해 원본 경로에 덮어쓴다.
- ✨ 코드가 안전한 건 별도 배관이 있어서가 아니라 `SKILL.md`의 제외 목록(`Code/commits/PRs`)에 명시적 예외로 적혀 있기 때문이다. 노트 산문에는 그 예외가 없다. 그래서 코드 레포에서는 켜도 되고, 노트가 곧 결과물인 이 볼트에서는 꺼두는 게 맞다.

---

**플러그인 scope는 디렉터리에 묶인다 — MCP가 안 뜨는 흔한 원인**

- ✨ `local` scope로 설치한 플러그인은 설치 당시의 `projectPath`에 묶인다. 다른 프로젝트에서는 등록조차 안 되고, MCP 서버도 당연히 안 뜬다. 증상이 "패키지 설치 문제"처럼 보여서 엉뚱한 데를 파기 쉽다.
- ✨ 진단 순서를 뒤집는 게 맞다. 패키지 매니저부터 뒤지지 말고 **플러그인 목록에서 scope와 enabled 상태를 먼저** 본다. 이번에도 `uvx`는 처음부터 정상이었고 `uv tool install`은 애초에 필요 없었다. 여러 프로젝트에서 쓸 도구는 처음부터 user 스코프로 넣는 게 낫다.

---

**우로보로스 스킬 문서의 실제 오류 2건**

- ✨ 문서가 안내하는 `uvx --from ouroboros-ai ouroboros detect`는 `claude` extra가 빠져 SDK를 못 찾고 실패한다. `ouroboros-ai[mcp,claude]`로 붙여야 동작한다.
- ✨ 브라운필드 기본값 "clear all" 경로(`set_defaults` + 빈 값)는 도구가 빈 문자열을 거부해서 실패한다(`Invalid indices: Must be comma-separated numbers`). 전부 지우려면 원하는 레포 하나로 덮어쓰는 식으로 우회해야 한다.
- ✨ 버전이 두 갈래로 갈려 있다. 마켓플레이스 매니페스트는 `0.50.5`를 광고하는데(GitHub 릴리스 태그는 `v0.50.6`), MCP 서버는 `uvx`가 매번 최신을 끌어와 `0.50.6`으로 뜬다. 스킬 파일만 구버전인 skew라 실사용엔 지장 없다.
