## 배운 것

<!-- claude-recall-learn:rlatjdwn:start -->

**"오타"와 "지문 미확인"은 다른 실수다 — 대응법도 다르다**

- ✨ 오늘 틀린 것을 뭉뚱그려 "오타"라고 부르면 대응을 놓친다. `binary_crossentroy`·`n_estimator`는 **손이 미끄러진 진짜 오타**로 `Tab`이 잡아주고 대개 에러가 난다. 반면 `ak`·`[:10]`·`"Epoch"`·`'features'`는 **지문을 안 본 것**이라 `Tab`도 문서도 못 잡는다 — 문제 문장에만 있는 정보이기 때문이다.
- ✨ 후자가 더 위험한 이유는 **전부 정상 동작한다**는 점이다. `import sklearn as ak`도 잘 돌고, `[:10]`도 그래프가 잘 나오고, `plt.xlabel("Epoch")`도 축 이름이 잘 붙는다. 화면만 봐서는 틀린 걸 모른다.
- ✨ 3칸이면 10점 안팎이고 커트라인이 80점이라 여유가 크지 않다. 그런데 **이건 실력이 아니라 습관**이라, 처방도 "한 번 더 읽기" 하나다.

**모델 이름 접미사 — 선형 계열만 규칙이 다르다**

- ✨ `LogisticRegression`은 이름이 "회귀"인데 **실제로는 분류 모델**이고, `Regressor`가 아니라 **`Regression`** 으로 끝난다. `LinearRegression`도 마찬가지다(이쪽은 진짜 회귀).
- ✨ 트리·숲(`DecisionTree`·`RandomForest`)과 XGBoost는 전부 `Regressor`/`Classifier` 짝인데, **선형 계열만 이 규칙에서 빠진다.** import 경로도 `sklearn.linear_model`이다.

**출력층과 loss의 짝, 그리고 `sparse_`의 자리**

- ✨ **`sigmoid` → `binary`, `softmax` → `categorical`** 이 기본 짝이다. 그리고 `sparse_`는 **`categorical_`에만 붙는다** — `sparse_binary_crossentropy`라는 건 존재하지 않는다. `binary`는 애초에 y가 0/1 한 칸이라 원핫 여부를 따질 게 없기 때문이다.
- ✨ 다중분류에서 **원핫을 하든 안 하든 결과는 같다.** 같은 시드로 돌려 보니 정확도 0.8070 vs 0.8066으로 소수점 셋째 자리에서만 갈렸고, 이건 방식 차이가 아니라 학습 중 난수 탓이다. 바뀌는 건 **y의 모양과 loss 이름 두 줄뿐**이고, 예측값은 둘 다 `(n, 2)` 확률 배열로 나와 `np.argmax(pred, axis=1)`로 똑같이 답을 뽑는다.
- ✨ 답 뽑는 법은 출력층이 결정한다 — `Dense(1, 'sigmoid')`는 `(pred > 0.5).astype(int)`, `Dense(2, 'softmax')`는 `np.argmax(pred, axis=1)`.

**Keras는 `compile` 시점에 loss 이름을 검증하지 않는다**

- ✨ 존재하지 않는 loss 이름을 넣어도 **`compile`은 그냥 통과한다.** `fit`을 돌려야 터진다. 그래서 "컴파일 셀에 에러가 없다"는 게 이름이 맞다는 증거가 되지 못한다.
- ✨ `evaluate`도 헷갈리기 쉽다 — **Keras 모델에만 있다.** sklearn 모델은 `model.score(X_valid, y_valid)`(분류면 accuracy, 회귀면 R²)이나 `accuracy_score(y_valid, model.predict(X_valid))`를 쓴다.
- ✨ `.h5` 저장 시 뜨는 **HDF5 legacy 경고는 무시해도 된다.** `WARNING`이지 `Error`가 아니고 `load_model`도 정상이다. 경고를 없애겠다고 `.keras`로 바꾸면 **문제가 준 파일명과 달라져 오히려 틀린다.**

**출제 근거가 있는 것과 개념 설명용을 구분해야 한다**

- ✨ `flatten`·`argmax`·`astype`은 **공식 샘플 2종에 전혀 없다.** 이유가 명확하다 — 딥러닝 예측값을 쓰는 문항 자체가 없기 때문이다. 문항 12는 sklearn 모델이라 `predict`가 바로 0/1을 주고, 문항 13은 학습만 하며, 문항 14는 `history`로 그래프만 그린다.
- ✨ 반면 `ModelCheckpoint`와 `load_model`은 **샘플 2종 모두의 import 블록에 들어 있다.** 시험이 굳이 넣어 준다는 건 쓸 수도 있다는 뜻이라 대비 대상이 맞다.
- ✨ 남은 시간이 짧을수록 이 구분이 중요하다. 개념 이해용으로 배운 것과 출제 대비를 섞으면 **없는 범위를 공부하게 된다.**

**[FE] 폴더는 종류가 아니라 기능으로 묶는다**

- ✨ 흔한 구조(`components/`·`hooks/`·`utils/`)는 **기능 하나를 고치려고 폴더 셋을 오가게** 만든다. 이 레포는 `features/upload/` 아래에 화면·부품·검증 로직·훅을 전부 모은다 — 기능을 통째로 지우려면 폴더째 지우면 된다.
- ✨ `lib`과 `features`를 가르는 기준은 **"이 코드가 우리 앱이 무엇을 하는 서비스인지 아는가"** 다. 모르면 `lib`(기술 유틸), 알면 `features`.

**[FE] 경계에서 검증한다 — 타입 술어와 `window` 가드**

- ✨ `value is Theme` 같은 **타입 술어**는 그냥 `boolean`과 다르다. `boolean`은 "참이다"까지만 말해서 `if`를 통과해도 컴파일러는 값이 여전히 아무 문자열이라고 본다. 술어를 붙여야 **"참일 때 이 값의 정체가 무엇인지"** 까지 알려준다. `localStorage`에 누가 `"보라색"`을 넣어 뒀을 수도 있으니 경계에서 걸러야 한다.
- ✨ `Record<K, V>`는 **K의 모든 값이 키로 있어야** 통과한다. 그래서 에러 사유를 하나 추가하면 문구 객체가 즉시 빨간 줄이 되고, 채워 넣을 때까지 빌드가 안 된다.
- ✨ Next.js는 **같은 코드를 서버(Node.js)와 브라우저에서 두 번 실행한다.** 서버에는 `window`도 `document`도 없어서 `typeof window === "undefined"` 가드가 필요하다 — `theme.ts` 한 파일에만 네 번 나온다.

**[마케팅] 거점시장은 "돈 낼 사람"으로 고르고, 키워드는 의도로 고른다**

- ✨ **제품 검증 타깃과 마케팅 타깃은 평가 축이 다르다.** 기존 문서의 판단 기준은 대학생 팀플을 검증 타깃으로 고른 것이고, "돈을 낼 사람"을 고를 때는 **지불 여력과 검색 수요 축이 추가**된다.
- ✨ 거점시장 선정은 시장 성립 3조건(같은 제품을 사고, 같은 판매 프로세스로 팔리고, 서로 입소문을 내는 집단인가)부터 본다. 세그먼트를 고를 때 **규모보다 반복성과 절박함**이 중요한데, 공모전이 밀린 이유가 정확히 그거였다 — 규모는 크지만 단발성이고 지불이 대행·첨삭으로 흡수된다.
- ✨ 키워드는 **"많이 검색되는 것"이 아니라 "검색한 사람이 돈 낼 사람인가"** 로 고른다. 니치 SaaS는 저볼륨·고의도 롱테일이 오히려 유리하다. 네이버 검색광고는 계정만 만들면 **키워드도구로 월간 검색량·경쟁도·예상 입찰가를 무료로** 볼 수 있고, 노출 순위는 `입찰가 × 품질지수`라 돈만 써서 1등이 되지는 않는다.
