## 배운 것

<!-- claude-recall-learn:rlatjdwn:start -->
**Firestore는 스키마 없는 DB라 잘못된 문서를 아무도 막지 않는다**

- ✨ 서버가 뭘 쓰든 Firestore는 받아준다. 그래서 필드 모양이 틀려도 쓰기 시점엔 아무 에러가 없고, **앱이 읽을 때 터진다.** 잘못된 모양 위에 UI를 짜면 나중에 서버·앱을 둘 다 고쳐야 하므로, `--backfill` 1회로 진짜 문서 하나를 만들어 콘솔에서 눈으로 보는 게 앱 코드 짜기 전 가장 싼 검증이다.
- ✨ 실제로 그 검증이 값을 했다. `deadline`이 33건 중 6건 `null`로 들어갔는데, 이게 설계가 작동한 증거다 — `_parse_deadline()`은 두 형식만 받고 실패 시 `None`을 반환하고, 상시모집처럼 마감일 없는 공고가 예외 없이 `null`이 됐다. 파생 플래그를 저장하는 옛 설계였다면 이 6건에 `is_closing_soon`을 뭘로 넣을지 정해야 했고, `False`로 두면 상시모집이 급한 공고와 구분되지 않았을 것이다.

**Firebase Admin SDK는 보안 규칙 밖에 있다**

- ✨ Admin SDK는 서비스 계정 키만 쓰며 **보안 규칙을 아예 우회한다.** 그래서 (a) Firebase 콘솔의 "앱 추가"는 클라이언트(Android/iOS/웹)용이라 서버만 있는 단계에선 불필요하고, (b) Firestore를 프로덕션(잠금) 모드로 만들어도 서버 쓰기는 정상이다. 앱을 만들 때 `notices` 읽기만 여는 규칙을 추가하면 된다.
- ✨ 반대로 그 키 파일 하나로 Firestore 전체 읽기·쓰기·삭제가 가능하다는 뜻이기도 하다. 그리고 콘솔이 보여주는 스니펫은 경로를 하드코딩하는데, 로컬 맥과 오라클 VM의 경로가 다르므로 **환경변수(`GOOGLE_APPLICATION_CREDENTIALS`)로 받아야** 코드를 그대로 두고 배포처마다 값만 바꿀 수 있다. 참고로 콘솔의 SDK 언어 토글은 화면 예제만 바꾸고, 다운로드되는 키 JSON은 언어와 무관하게 동일하다.
- ✨ Firestore **위치는 한 번 정하면 못 바꾼다** — 프로젝트를 지우고 다시 만들어야 한다.

**[[결정 기록|ADR]]을 쓰면 결정들이 독립이 아니라 사슬이라는 게 드러난다**

- ✨ 이번에 쓴 3건이 정확히 그랬다. `0001 파생 상태 미저장` → (신규 판별 근거가 "문서 존재" 하나만 남음) → `0002 발송 후 저장` → (앱이 임박 계산을 떠맡음) → `0003 capacity만 nullable`. **0001을 되돌리면 0002·0003의 존재 이유가 사라진다.**
- ✨ ADR이 없었다면 나중에 누군가 "0002는 순서가 이상한데, 저장부터 하는 게 자연스럽지 않나" 하며 바꿨을 것이다 — 0001을 모르니까. 이제 0002 문서를 열면 첫 줄이 0001로 링크된다. 산문에 흩어진 근거와 달리 **날짜·대안·기각 사유가 함께 남는 것**이 ADR 형식의 값이다.

**타깃 유저 선정은 취향이 아니라 절차가 있다**

- ✨ 업계 통용 흐름은 4단계다: ① 문제를 겪는 후보 세그먼트 나열 → ② 기준표로 채점해 **하나의 좁은 beachhead(교두보) 시장** 선정 → ③ 그중에서도 지금 당장 쓸 얼리어답터 식별 → ④ 검증. ②의 기준은 MIT *Disciplined Entrepreneurship*·『Crossing the Chasm』 계열에서 대체로 수렴한다 — pain 강도·빈도 / 도달 가능성 / 도입 장벽 / 지금 역량으로 완전한 제품을 줄 수 있는가 / 그 집단 안에서 입소문이 도는가 / 다음 시장으로 건너갈 발판인가.
- ✨ **타깃이 갈리면 실제로 문서가 갈라진다**는 게 이번에 확인한 핵심이다. 대학생이면 "링크만 있으면 비회원도 코멘트"가 필수 정책이지만(교수·조교는 절대 가입하지 않으므로), 직장인이면 정반대로 "초대된 계정만 접근"이 기본이고 게스트 기능은 보안 리스크가 된다. 파일 형식도 docx/pdf(텍스트 diff로 MVP 성립) 대 hwp·xlsx(한국 특화 파싱 난제 + 셀 단위 diff라는 다른 엔진)로 갈리고, 이력의 성격도 편의 기능 대 증빙·감사용으로 갈린다.
- ✨ 그래서 이번엔 **비전 차원의 일반화(워크플로 기준)와 1차 검증 페르소나(beachhead)를 분리**해 확정했다. 코어 기능 정의는 두 페르소나가 공유하는 루프에서 뽑고, 정책·UX 세부는 beachhead 하나를 기준으로 결정하는 방식이다.

**"완주"는 도구의 성공을 뜻하지 않는다 — 관측 가능한 성공 기준 설계**

- ✨ "한 팀이 과제 1건을 이 도구로 완주하면 성공"은 직관적이지만 함정이 3개다. ① 대학생은 마감 압박 때문에 **불편해도 어떻게든 완주**한다 → 완주는 도구가 아니라 팀의 절박함을 측정한다. ② 옆에서 운영자가 버그를 우회해 주면 완주하는데 그건 도구의 힘이 아니다. ③ 팀원끼리 코멘트만 주고받고 **핵심 기능(AI 매칭)을 건너뛰어도 완주는 성립**한다 → 그럼 검증된 건 그냥 게시판이다.
- ✨ 그래서 기준을 **AND로 묶고 표본을 늘렸다** — 3팀 이상 파일럿에서 무개입·무이탈·AI 매칭 실사용을 모두 만족하는 팀이 1팀 이상. 원인 귀속이 안 되는 1팀 1건 대신, 루프를 단계로 쪼개 **어디서 끊기는지 계측**하고 개입 여부를 기록한다.
- ✨ 더 깊은 구멍은 **"반영"과 "검토"가 다른 사람의 행위**라는 점이었다. AI 매칭을 확정하는 건 문서를 고친 편집자지만, 성공 기준의 "검토"는 피드백을 준 사람이 "내 지적이 해소됐다"고 확인하는 행위다. 편집자가 혼자 닫은 걸 검토로 치면 검토를 **관측한 게 아니라 가정한 것**이 된다. 다만 원작자만 닫을 수 있게 하면 게스트가 다시 안 들어와 루프가 영영 안 닫히므로, 여기엔 정답이 아니라 트레이드오프가 있고 그걸 정책 문서에 명시해 두는 게 맞다.
- ✨ 상태 설계 쪽 교훈도 하나. "검토 완료"를 **별도 상태 머신으로 만들지 말고 "모든 피드백이 닫힘"의 파생 집계로 처리**하면 기능이 늘지 않는다 — 쿼리로 계산하면 공짜다. 계산 가능한 것을 저장하지 않는다는 점에서 SSUNoti의 "파생 상태 미저장"과 같은 원리다.

## 메모

- **SSUNoti 서버 단계는 종결됐지만 병합 전이다.** PR [#1](https://github.com/Kimseongju7/ssunoti/pull/1)에 `ooo/run/seed_262eebbaf895` 브랜치가 올라가 있고 `main`에는 아직 안 들어갔다. 다음 선택지는 세 갈래 — PR 병합으로 서버 단계 종결 / Flutter 앱 착수(이제 Firebase 프로젝트가 있으니 topic `new_notices` 구독 + Firestore 리스닝이 가능하고, **FCM 실발송도 이때 처음 검증된다**) / 오라클 VM 상주 배포. 지금 Firestore의 33건은 오늘 시점 스냅샷이라, 앱을 만드는 몇 주 동안 서버가 안 돌면 그사이 신규 공고를 놓친다.
- **커버리지 47%는 의도적으로 남긴 빚이다.** 원인은 `crawler.py` 15% 하나이고, 오프라인 파싱 테스트를 붙이려면 학번을 마스킹한 HTML 샘플을 새로 만들어 커밋해야 한다. 이번 PR 범위 밖으로 분리했으니 별도 작업으로 잡아야 한다.
- **geul-hub는 산출물 생성 직전에서 멈춰 있다.** 확정 사항을 바탕으로 네 문서(mvp_user_story·policy·기능명세서·용어집)와 `docs/decisions/` 결정기록을 만들면 되고, 최종 확인 중이던 목록은 세 가지다 — 정책 문서에 명시할 알려진 트레이드오프 3건(게스트 느슨한 식별에 따른 사칭 가능성 / 누구나 피드백을 닫을 수 있어 검토 신호가 약해질 수 있음 / 텍스트 추출 기반 diff라 레이아웃·서식 변경은 감지 불가), 결정기록에 남길 painpoint 문서 개정 2건(AI diff 요약 MVP 제외, 타깃 판단 5기준 채점 근거), 2차 이월 통합 목록(직장 조직 전용 요구 — 계정 접근통제·불변 감사이력·xlsx 셀 diff·hwp 정밀 diff·결재선 / pptx diff / 버전 단위 "검토 완료" 승인 도장 / 역할 위계·문서별 권한 / 팀원 전원 검토 추적 / AI diff 요약).
- 블로그에 남은 잔손질 하나 — 기존 포스트 2편(`feature-engineering`, `confusion-matrix`)에 `[["면적", "층수"]]` 형태의 **가짜 위키링크**가 남아 있다. 코드 예시의 리스트 리터럴이 위키링크로 오인된 것이다.
