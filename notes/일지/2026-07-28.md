## 배운 것

**파생 상태를 저장하면 원본이 바뀔 때 동기화 책임이 생긴다**

- ✨ "정원 90% 도달" 플래그를 래치로 두면 정원이 10명 → 30명으로 **증액**될 때 9/10(90%, 플래그 ON)이 9/30(30%)이 되는데도 플래그가 영원히 남아 앱이 거짓 "임박" 배지를 띄운다. 잔여석 절대값도 같은 문제를 겪는다. 마감일도 연장될 수 있으니 `notified_deadline`에도 똑같은 논리가 적용된다.
- ✨ 그래서 결론이 **원시값(`applicant_count`/`capacity`/`deadline`)만 저장하고 임박 판정은 읽는 쪽이 계산**하는 쪽으로 갔다. 판단을 저장하지 않으면 동기화할 것도 없다. [[YAGNI]]가 성능이 아니라 정합성 문제로 나타난 사례.

---

**스키마 불일치는 '검증 실패'보다 '조용한 폐기'가 위험하다**

- ✨ pydantic 모델은 기본값 `extra=ignore`라 모르는 필드를 **에러 없이 버린다**. 우리 Seed의 `verification`·`blocking`·`invariants`가 전부 그 대상이었다. 이번엔 다른 필드명(`statement` vs `description`)이 검증 실패를 일으켜 운 좋게 드러났지, 이름이 우연히 다 맞았다면 AC1의 blocking 속성이 사라진 채 실행됐을 것이다.
- ✨ 교훈은 **경계에서 스키마를 먼저 확인하라**는 것이다. "사람이 읽는 명세"와 "실행 계약"은 같은 YAML처럼 보여도 다른 물건이다.

**우로보로스에는 '프로젝트'가 1급 개체로 존재하지 않는다**

- ✨ 설치는 전역이고 DB도 `~/.ouroboros/ouroboros.db` 하나다(`database_path` 설정은 문서에 "EventStore가 아직 존중하지 않음"으로 명시). 프로젝트별로 갖는 건 `.ouroboros/mechanical.toml`과 guidance뿐. 인터뷰·[[Seed 스펙|시드]]·세션은 전부 ID로만 구분되어 홈 디렉토리에 섞인다. **한 번에 프로젝트 하나가 전제**다.
- ✨ 프로젝트 디렉토리 해석 순서는 `explicit working_dir → brownfield default → seed metadata → session cwd`. cwd가 가장 약한 고리라 brownfield default가 "지금 작업 중인 프로젝트"를 알려주는 사실상의 공식 수단이다. 업스트림 이슈 #1389("Project Map")가 열려 있고 메인테이너도 로드맵을 손으로 편집 중 — 즉 **커뮤니티도 아는 미해결 설계 질문**이다.
- ✨ ambiguity는 LLM이 채점한다(`temperature=0.1`). goal/constraint/success 차원별 clarity를 가중합해 `1 − Σ(clarity×weight)`로 계산하고, brownfield에는 `context_clarity` 0.15가 추가된다. 임계값 0.2 이하면 [[Seed 스펙]] 생성 가능.
- ✨ `ooo auto`는 **기존 seed를 이어받지 않는다.** 자기 [[소크라테스 인터뷰]]를 처음부터 다시 돌려 자기 seed를 만든다. 기존 seed를 그대로 실행하는 건 `ooo run`, 부모로 삼아 파생시키는 건 `ooo evolve`다.

**파이썬 상주 프로세스와 환경 관리 — APScheduler, uv vs venv**

- ✨ **APScheduler는 하나의 프로세스 안에서 도는 스케줄러**라 OS cron과 결정적으로 다르다. cron은 실행할 때마다 프로세스를 새로 띄우므로 매번 SSO 3단계 재로그인이 필요하지만, APScheduler는 크롤러 인스턴스와 세션(JSESSIONID)을 메모리에 유지한다. 학교 서버 부하 제약이 있는 이번 설계에서는 이게 곧 오라클 상시 VM을 고른 이유가 된다.
- ✨ **uv와 venv는 경쟁 관계가 아니라 층이 다르다.** venv는 결과물(격리된 상자)이고, uv는 그걸 만들고 관리하는 도구다 — 가상환경 생성·패키지 설치·잠금·파이썬 버전 관리를 하나로 합친 것. uv도 내부적으로 venv를 만든다. `uv run pytest`는 activate 없이 그 환경으로 실행해 주므로, `python -m pytest`가 엉뚱한 파이썬을 집는 사고를 막아준다.

---

**실행 전에 걸리는 안전장치가 비용을 아낀다**

- ✨ `git worktree add`는 **깨끗한 체크아웃**을 전제한다. 추적되지 않은 파일이 있으면 나중에 워커 산출물과 구분할 수 없기 때문이다. 이건 버그가 아니라 의도된 안전장치이고, 실제로 파일을 하나도 건드리기 전에 막혔다.
- ✨ **`.env`만 gitignore하면 안전하다고 생각하기 쉽지만 크롤링 샘플 HTML이 우회로가 된다.** 로그인 상태로 받은 페이지에는 헤더의 이름, 마이페이지 링크 쿼리 파라미터 등에 식별 정보가 그대로 남는다. git은 커밋을 되돌려도 히스토리에 남으므로, 한 번 들어가면 `git rm`으로는 못 지운다.

---

**공기업 지원 기준은 '들어갈 수 있냐'와 '들어간 뒤'를 갈라야 한다**

- ✨ 흔히 만드는 비교표는 초임·워라밸·위치 같은 **입사 후 삶의 질** 컬럼으로 채워지는데, 정작 합격 가능성(필기 유형, 어학 커트, 가점 자격증, 전산직 기준 경쟁률)이 통째로 빠져 있다. 후자가 없으면 순위는 실행 계획이 못 된다.
- ✨ 그래서 **탈락 필터(Yes/No) → 합격 가능성 → 선호 가중(여기서만 점수)** 3층으로 나누는 게 맞다. 1층을 통과 못 하면 나머지 비교 자체가 무의미하므로 점수를 매기지 말고 딱 잘라야 한다.
