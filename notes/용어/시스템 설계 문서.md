## 한 줄 정의
[[PRD]]가 정한 "무엇을"을 **"어떻게"로 옮기는 문서** — 컴포넌트 구성, 데이터 흐름, 인터페이스, 실패 시 동작을 그림과 표로 못 박는다.

## 자세히
PRD는 의도적으로 해법을 비워 둔다. 그 빈칸을 채우는 게 설계 문서다. 여기서 처음으로 "Redis로 캐싱한다", "인증은 JWT" 같은 문장이 정당해진다. 순서를 뒤집어 설계부터 쓰면 문제 정의가 해법에 끌려가므로, PRD → 설계 순서를 지키는 게 중요하다.

담기는 항목은 대체로 이렇다.

| 항목 | 내용 |
|---|---|
| **아키텍처 개요** | 컴포넌트와 그 경계. 다이어그램 1장 |
| **데이터 흐름** | 요청이 어디서 어디로, 무엇이 어떻게 변형되나 |
| **인터페이스 / API** | 엔드포인트, 요청·응답 형식, 에러 코드 |
| **데이터 모델** | 저장 구조 ([[ERD]]로 분리하기도) |
| **비기능 요구** | 성능·확장성·보안 목표치 |
| **실패 시나리오** | 의존 서비스가 죽으면 어떻게 되나 |
| **대안과 기각 사유** | 왜 이 구조인가 ([[결정 기록]]으로 분리하기도) |

가장 자주 빠지는 게 **실패 시나리오**다. 정상 경로만 그린 설계는 구현 단계에서 반드시 "이럴 땐 어떻게 하죠?"로 되돌아온다. 외부 API가 타임아웃 나면, DB 커넥션이 마르면, 중복 요청이 오면 — 이 질문들의 답이 설계에 없으면 각자 다르게 처리하고, 시스템 전체의 동작이 예측 불가능해진다.

또 하나. 설계 문서는 **읽는 사람이 정해져 있다.** 구현자가 이걸 보고 코드를 짤 수 있어야 한다. 그래서 "확장 가능하고 유연한 구조"처럼 판정 불가능한 문장은 쓸모가 없다 — [[AC 트리]]의 나쁜 AC와 같은 실패다. "인스턴스를 늘려 수평 확장 가능(상태를 인스턴스에 두지 않음)"처럼 검증 가능한 문장으로 적어야 한다.

분량은 프로젝트 크기에 따른다. 개인 프로젝트라면 다이어그램 1장 + API 표 한 개로 충분하고, 규모가 커지면 ERD와 [[결정 기록|ADR]]을 별도 문서로 떼어낸다. 문서를 나누는 기준은 **수명**이다 — 자주 바뀌는 것(API 상세)과 오래 가는 것(왜 그 구조인가)을 한 파일에 섞지 않는다.

## 예시
```markdown
# 시스템 설계 — 로컬 할 일 관리 CLI

## 아키텍처
  cli.py (인자 파싱)
    └─ core/todo.py (도메인 로직, 순수 함수)
         └─ storage/json_store.py (파일 I/O)

의존 방향은 항상 안쪽(도메인)으로. 도메인은 파일 시스템을 모른다.

## 데이터 흐름
todo add "리뷰"
  → parse → TodoItem(id=auto, text, archived=False)
  → load(~/.todo.json) → append → atomic write(tmp + rename)

## 인터페이스
| 명령 | 인자 | 종료 코드 |
|---|---|---|
| add  | text (필수, 비어있으면 안 됨) | 0 / 1(빈 입력) |
| list | --archived | 0 |
| done | id | 0 / 2(없는 id) |

## 실패 시나리오
- 파일 손상(JSON 파싱 실패) → 원본을 .bak 로 보존, 빈 목록으로 시작, stderr 경고
- 쓰기 중 프로세스 종료 → tmp 파일에 쓰고 rename 하므로 원본 무손상
- 동시 실행 2개 → 마지막 쓰기 승리 (단일 사용자 전제, 비범위)

## 비기능
- 1만 건 목록 조회 200ms 이내
- 외부 네트워크 호출 없음
```

## 관련
- [[PRD]] — 이 문서가 답하려는 "무엇을/왜"가 정의된 상위 문서
- [[ERD]] — 데이터 모델을 따로 떼어낸 문서
- [[결정 기록]] — "왜 이 구조를 골랐나"를 별도로 보존하는 문서(ADR)
- [[AC 트리]] — 설계가 만족시켜야 할 검증 가능한 조건
- [[Seed 스펙]] — 설계 결정을 `architecture_decisions`로 담는 AI 워크플로용 형식
- [[마이크로서비스 아키텍처]] · [[모놀리스 애플리케이션]] — 설계 문서가 고르는 대표적인 구조 선택지
