## 한 줄 정의
Lateral thinking — 지금 가던 방향으로 더 파는 대신 **문제를 옆에서 다시 정의해** 막힌 지점을 우회하는 사고법.

## 자세히
에드워드 드 보노가 만든 용어다. 수직적 사고(vertical thinking)가 하나의 논리 사슬을 깊게 파 내려간다면, 측면 사고는 **사슬 자체가 잘못 걸려 있을 가능성**을 의심한다. 막혔을 때 흔한 실패는 같은 접근을 더 열심히 반복하는 것인데, 접근이 틀렸다면 노력의 양은 아무것도 바꾸지 못한다.

AI 에이전트 루프에서 이 문제는 더 심하다. 에이전트는 지치지 않으므로 잘못된 방향으로도 무한히 팔 수 있다. 그래서 [[우로보로스 사용법|Ouroboros]]는 `unstuck` 단계에 **5개 페르소나**를 두고 서로 다른 렌즈로 같은 문제를 다시 보게 한다.

| 페르소나 | 태도 | 쓸 때 |
|---|---|---|
| **hacker** | 일단 돌게 만들어, 우아함은 나중 | 과한 고민이 진행을 막을 때 |
| **researcher** | 우리가 모르는 정보가 뭐냐 | 문제가 불명확할 때 |
| **simplifier** | 스코프 잘라, MVP로 돌아가 | 복잡도가 감당 안 될 때 |
| **architect** | 접근 자체를 재구성 | 현재 설계가 틀렸을 때 |
| **contrarian** | 우리가 틀린 문제를 풀고 있는 거 아니냐 | 가정을 흔들어야 할 때 |

이 다섯은 **상태 없는(stateless) 사고방식 렌즈**다. 진행 상황을 기억하거나 판정 권한을 갖지 않는다. `evaluator`(검증)나 `ontologist`(근본 원인 규명)처럼 상태와 책임이 있는 역할은 이 풀에 섞이지 않고 각자 별도 스킬로 존재한다. 렌즈와 심판을 섞지 않는 게 설계 포인트다.

기본 동작은 5인 전원 토론(`ooo lateral`)이고, 특정 페르소나만 부르거나(`ooo lateral contrarian`) 둘셋만 붙여 토론시킬 수도 있다(`ooo lateral debate hacker simplifier`). [[PAL 라우팅]]에서 이 호출의 기본 티어가 `frontier`로 잡혀 있는데, 창의적 재구성은 모델 능력을 실제로 요구하는 몇 안 되는 작업이기 때문이다.

## 예시
```
상황: "결제 실패율이 높다" → 3일째 재시도 로직만 손보는 중

hacker      : 재시도 말고 실패 건을 큐에 넣고 나중에 배치로 처리하면 되지 않나
researcher  : 실패 응답 코드 분포를 본 적 있나? 카드사별로 다를 텐데
simplifier  : 카드 결제 하나만 남기고 나머지 수단을 잠시 내리자
architect   : 동기 결제를 비동기 승인 모델로 바꾸면 재시도가 필요 없어진다
contrarian  : 실패율이 문제인가, 아니면 실패한 사용자가 이탈하는 게 문제인가?
              후자면 고칠 건 결제가 아니라 실패 화면이다
```
마지막 한 줄에서 문제 정의 자체가 바뀐 게 측면 사고의 전형이다.
