## 1. CUB — 한 단계 더 저수준인 라이브러리

CUB은 Thrust보다 조금 더 low level의 라이브러리다. 안전장치가 없어서 C 언어에 더 가깝고, 그만큼 안전장치를 직접 건드려야 한다.

### 동기 vs. 비동기

Thrust는 안전장치가 모두 되어 있어서 동기식으로 처리한다. 반면 CUB은 안전장치 없이 그냥 던져 놓고 가버린다 — 방치형 육아에 가깝다.

![[Pasted image 20260912141200.png|221]]

Thrust와 달리 CUB은 시간을 재봐도 개수에 따라 실행 시간이 달라지지 않는다. 저 시간은 잘못 측정된 시간이다.

명시적으로 동기화하는 것이 `cudaDeviceSynchronize`다.

![[Pasted image 20260912141243.png|600]]![[Pasted image 20260912141259.png|228]]

이렇게 기다려주는 함수를 써야만 제대로 측정할 수 있다. CUB은 좀 더 로우 레벨의 라이브러리이기 때문에, 제어장치를 알고 쓰지 않으면 원하는 결과를 얻을 수 없다.

![[Pasted image 20260912141519.png|550]]

CUB을 쓰면 작업을 쪼개서 실행시킬 수 있다.

## 2. Nsight Systems와 NVTX

**Nsight Systems** 는 GPU가 돌아가는 모습을 시각화해서 보여주는 분석 도구다. (nsight 비밀번호 : `nvidia`)

**NVTX** 는 일종의 주석이다. 내가 작업하려는 특정 range에 문구를 넣어두면, 작성한 대로 Nsight에 표기된다.

## 3. 실습 — Thrust를 CUB으로 바꿔보기

```c++
void simulate(int height, int width, 
              thrust::device_vector<float> &in, 
              thrust::device_vector<float> &out) 
{
  cuda::std::mdspan temp_in(thrust::raw_pointer_cast(in.data()), height, width);
  thrust::tabulate(
    thrust::device, out.begin(), out.end(), 
    [=] __host__ __device__(int id) { /* ... */ }
  );
}

for (int write_step = 0; write_step < 3; write_step++) 
{
  thrust::copy(d_prev.begin(), d_prev.end(), h_prev.begin());
  dli::store(write_step, height, width, h_prev);

  for (int compute_step = 0; compute_step < 3; compute_step++) {
    simulate(height, width, d_prev, d_next); // GPU 작업을 한다
    d_prev.swap(d_next);
  }
}
```

Thrust는 GPU 작업을 기다린 다음에 파일에 쓴다.

![[Pasted image 20260912145258.png|581]]

CPU가 아무것도 안 하고 기다리고만 있다. 이렇게 하지 말자. CUB을 사용해서 CPU를 놀리지 않는다.

![[Pasted image 20260912145449.png|347]]

```C++
  auto begin = std::chrono::high_resolution_clock::now();

  if (use_cub) 
  {
    auto cell_ids = thrust::make_counting_iterator(0);
    cub::DeviceTransform::Transform(cell_ids, out.begin(), width * height, compute); // 
  }
  else 
  {
    thrust::tabulate(thrust::device, out.begin(), out.end(), compute);
  }
  auto end = std::chrono::high_resolution_clock::now(); // cub 사용 시 결과를 기다리지 않고 바로 실행
  return std::chrono::duration<float>(end - begin).count();
}
```

![[Pasted image 20260912145644.png|424]]

보면 CUB 시간은 크게 달라지지 않는다. Thrust의 안전장치를 풀고 제어권을 가져온 셈이다.

여기에 `cudaDeviceSynchronize`를 넣어 실행 완료를 기다리게 하면:

```C++
  auto begin = std::chrono::high_resolution_clock::now();

  if (use_cub) 
  {
    auto cell_ids = thrust::make_counting_iterator(0);
    cub::DeviceTransform::Transform(cell_ids, out.begin(), width * height, compute);
    cudaDeviceSynchronize(); // 실행이 완료 되기를 대기
  }
  else 
  {
    thrust::tabulate(thrust::device, out.begin(), out.end(), compute);
  }
  auto end = std::chrono::high_resolution_clock::now();
  return std::chrono::duration<float>(end - begin).count();
}
```

둘의 차이는 조금 더 빨리 끝난다는 것.

### CUB으로 옮길 때 주의할 점

Thrust와 달리 CUB은 알고리즘의 개수를 직접 넣어줘야 한다 (= 실수의 여지가 있다).

```c++
cub::DeviceTransform::Transform(input_iterator, output_iterator, num_items, op);
```

또 CUB에는 `tabulate`가 없기 때문에, `counting_iterator`와 `transform`을 섞어서 쓴다.

Thrust 버전:

```C++
void simulate(int width,
              int height,
              const thrust::device_vector<float> &in,
                    thrust::device_vector<float> &out)
{
  cuda::std::mdspan temp_in(thrust::raw_pointer_cast(in.data()), height, width);
  thrust::tabulate(out.begin(), out.end(), [=] __device__(int id) {
    return dli::compute(id, temp_in);
  });
}
```

이걸 CUB 버전으로:

```C++
void simulate(int width, int height, const thrust::device_vector<float> &in,
                thrust::device_vector<float> &out) {
    cuda::std::mdspan temp_in(thrust::raw_pointer_cast(in.data()), height, width);
    cub::DeviceTransform::Transform(
        thrust::make_counting_iterator(0), out.begin(), width * height,
        [=] __host__ __device__(int id) { return dli::compute(id, temp_in); });
  }
```

## 4. CUDA Stream

지금까지는 하나의 GPU 공간에서만 작동한 것이라, 동시에 여러 개의 함수를 실행시킨 것이 아니다.

![[Pasted image 20260912151318.png|498]]

컴퓨팅이 복사가 완료될 때까지 불필요하게 기다린다. `cudaMemcpyAsync`를 쓰면 CUB에서처럼 함수를 호출하고 바로 다음으로 넘어간다.

![[Pasted image 20260912151445.png|504]]

복사하려는 데이터의 정확한 크기를 계산해서 바이트 단위로 넣어주어야 하고, 복사 방향도 넣어야 한다.

GPU에서 발생하는 에러는 실시간으로 잡기가 어렵다. 타입을 보고 제대로 판단해야 한다.

### 스트림의 규칙

- CUDA stream 지정이 없으면 default stream이 사용된다.
- 같은 스트림 안에서는 선언한 함수 순서대로 실행된다.
- 스트림은 하나 이상 가질 수 있고, 서로 다른 스트림에 대한 작업은 동시에 실행할 수 있다.
- 스트림끼리는 병렬 실행이 가능하고, 서로 다른 스트림 사이에서는 순서가 보장되지 않는다.
